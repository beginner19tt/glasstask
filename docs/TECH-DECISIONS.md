# 技術選定とその理由

すべての採用理由と、採用しなかった選択肢を並べる。
前提となる制約は 3 つ。

1. **開いた瞬間にメモできる** — 起動から入力可能までネットワークを挟まない。
2. **モバイルファースト** — 片手・親指・不安定な回線。
3. **Cloudflare 上で完結** — ランタイム・DB・AI・配信を 1 つの `wrangler deploy` に収める。

以下の判断はすべてこの 3 つから逆算している。

---

## ランタイム: Cloudflare Workers

| | |
|---|---|
| 採用 | Cloudflare Workers (workerd) |
| 代替 | Node.js on Fly.io / Vercel Functions / AWS Lambda |

- **コールドスタートが実質ゼロ。** V8 isolate なのでコンテナ起動が無い。Lambda の数百 ms〜数秒のコールドスタートは「開いた瞬間」という要件と直接衝突する。
- **エッジで動く。** 日本からのリクエストが東京の PoP で終わる。初回 `/api/me` が速いほどスケルトンが短い。
- 静的アセット配信・DB・AI・認証をすべて同じ Worker に同居させられるので、CORS もプロキシ設定も不要。
- **トレードオフ:** Node API が部分的にしか使えない。`nodejs_compat` を入れてはいるが、依存は Web 標準 API（`crypto.subtle`, `fetch`, `URL`）だけで組んだので実質問題にならない。

## HTTP ルーティング: Hono

| | |
|---|---|
| 採用 | Hono 4 |
| 代替 | 素の `fetch` ハンドラ / itty-router / tRPC |

- Workers 向けに設計されていて、**bundle が数 KB**。Worker のサイズ制限に効く。
- `c.env` が型付きで、`wrangler types` が生成した `Env` とそのまま噛み合う。バインディングの typo がビルドで落ちる。
- `hono/cookie` だけで Cookie の署名以外の面倒を全部見てくれる。
- **素の `fetch` ハンドラにしなかった理由:** ルートが 10 本を超えた時点で自前のパスマッチングは事故る。
- **tRPC にしなかった理由:** クライアントが 1 つしかなく、API は 8 本。型共有は `shared/` で足りるので、RPC レイヤーは純粋な重量増。

## データベース: Cloudflare D1

| | |
|---|---|
| 採用 | D1 (SQLite) |
| 代替 | Durable Objects / KV / Neon・Supabase (Postgres) |

- **タスクは関係データ。** ユーザーごとの絞り込み、ステータス別の集計、期限順の並べ替え。SQL が素直に効く。
- Worker と同じプラットフォームなので、接続プールもレイテンシ予算の心配もない。
- **KV にしなかった理由:** 結果整合。フリックでステータスを変えた直後に古い値が返ると、UI が巻き戻って見える。これは致命的。
- **Durable Objects にしなかった理由:** 強整合は得られるが、ユーザーごとに DO を立ててクエリを自前で書くことになる。今の要件に対して過剰。
- **外部 Postgres にしなかった理由:** エッジから別リージョンの DB を叩くと、せっかくのエッジが帳消しになる。
- **トレードオフ:** D1 には書き込みスループットの上限がある。個人のタスク管理では当たらない。当たる規模になったら DO + D1 のハイブリッドに移す。

### スキーマ上の判断

- `tags` は JSON 文字列の 1 カラム。正規化して `task_tags` テーブルを作ると、タスク 1 件の取得に JOIN が増える。タグで横断検索する要件が出るまでは非正規化が正しい。
- 削除は `deleted_at` によるソフトデリート。端末間同期で「片方で消したものが復活する」事故を防げる。
- インデックスは 2 本だけ。`(user_id, deleted_at, updated_at DESC)` が一覧クエリをそのまま覆う。

## AI: Workers AI (`@cf/meta/llama-3.3-70b-instruct-fp8-fast`)

| | |
|---|---|
| 採用 | Workers AI |
| 代替 | OpenAI / Anthropic API |

- **バインディング経由で呼べる。** API キーの保管も外向きの HTTP も不要。`env.AI.run()` だけ。
- 推論がエッジ側で走るので、外部 API への往復が無い。
- `fp8-fast` 版はメモの整形という短いタスクに対して十分な品質で、レイテンシとコストが低い。
- **設計上いちばん重要な点:** AI は**常にオプション**。`shared/parse.ts` の決定的パーサが先に走って使えるタスクを作り終えている。モデルがタイムアウトしても、JSON を返さなくても、キャプチャは一切ブロックされない。`mergeStructured()` は AI の結果を**加算するだけ**で、ユーザーが明示した `!` や日付を上書きしない。
- **トレードオフ:** Workers AI にはローカルエミュレータが無い。そのため `vite dev` は既定でリモートバインディングを切ってある（`vite.config.ts` 参照）。ローカルでは AI ルートが決定的パーサにフォールバックするので、Cloudflare アカウント無しでもアプリは一通り動く。

## 認証: Google OAuth 2.0 + PKCE、署名付き Cookie セッション

| | |
|---|---|
| 採用 | 自前実装（Worker 内、約 190 行） |
| 代替 | Auth.js / Clerk / Cloudflare Access |

- 要件が「**Google のみ**」。プロバイダ 1 つに抽象化レイヤーは要らない。
- **PKCE (S256)** を使うのは、`code` が漏れても交換できないようにするため。state は短命の署名付き Cookie に入れるので、OAuth 用のテーブルも KV も不要。
- `id_token` の署名検証を省いているのは、トークンを **Google のトークンエンドポイントから TLS で直接受け取っている**ため。ブラウザを経由していないので中間者がいない。implicit flow なら検証必須だが、この経路では不要（`worker/auth.ts` にコメントで明記）。
- **セッションは HMAC-SHA256 署名付きの HttpOnly Cookie。** セッションテーブルを引かないので、**認証済みリクエストの D1 読み取りが 0 回**になる。これが「開いた瞬間」のコールドパスを速く保つ。
  - **トレードオフ:** サーバ側で個別に失効できない。全失効は `SESSION_SECRET` のローテーションで行う。TTL は 30 日。
- **Auth.js にしなかった理由:** Workers 対応はあるが、プロバイダ 1 つに対して依存と設定が重い。
- **Clerk にしなかった理由:** 外部サービスが 1 つ増え、ログインのたびに外部往復が増える。

## フロントエンド: React 19 + TypeScript + Vite

| | |
|---|---|
| 採用 | React 19, TypeScript, Vite 8 |
| 代替 | Svelte / Solid / Next.js / Remix |

- **React:** フリックのジェスチャ状態、楽観更新、リスト再配置のアニメーションが絡む。`framer-motion` の `layout`/`AnimatePresence` がこの 3 つを一度に解決する。同等の成熟度を持つものが他に無い。
- **Vite:** HMR が速く、`@cloudflare/vite-plugin` が **Worker を workerd 上で、フロントと同じ dev サーバで**動かしてくれる。つまりローカルの `/api/*` が本番とほぼ同じランタイムで動く。プロキシ設定が要らない。
- **Next.js / Remix にしなかった理由:** このアプリに SSR の利点が無い。**ログイン前でもタスクが localStorage から即座に出る**のが望ましく、サーバでの初回レンダリングはむしろ邪魔。SPA + 静的アセットが要件に合う。
- **Svelte / Solid にしなかった理由:** 軽いのは事実だが、モーションのエコシステムが React ほど厚くない。アニメーションが要件の中心なのでここは譲れない。

## 状態管理: 自前の local-first フック（`src/lib/store.ts`）

| | |
|---|---|
| 採用 | `useStore()` + localStorage |
| 代替 | Zustand / Redux / TanStack Query |

- **書き込み順序が「React state → localStorage → ネットワーク」。** 入力がネットワークより遅くなることが構造的に起きない。
- 失敗した書き込みは `queue` に id が残り、次回ログイン時に `/api/tasks/sync` で一括再送される。**サインイン前に書いたメモも消えない。**
- **TanStack Query にしなかった理由:** サーバを信頼の中心に置くモデル。このアプリはローカルが中心でサーバは同期先なので、方向が逆。
- **Redux にしなかった理由:** 状態が 1 つのフックに収まる規模。

## アニメーション: Framer Motion

| | |
|---|---|
| 採用 | framer-motion |
| 代替 | CSS トランジション / GSAP / React Spring |

- **`drag="x"` がそのままフリックになる。** `offset` と `velocity` が `onDragEnd` で取れるので、「遠くまで動かした」と「速く弾いた」の両方を 1 か所で判定できる（`shared/flick.ts`）。
- **`layout` と `AnimatePresence`** で、ステータス変更によるリスト再配置が自動的にスプリングで補間される。手書きでこれを正しくやるのは現実的でない。
- **`layoutId`** でレール上のピルがタブ間を滑る。
- CSS だけでは、ドラッグ中の位置に応じて背景のラベル（`TODAY ›`）の不透明度を連動させられない。`useMotionValue` + `useTransform` が必要。

## スタイル: 素の CSS（Tailwind なし）

| | |
|---|---|
| 採用 | 手書き CSS + カスタムプロパティ |
| 代替 | Tailwind / CSS-in-JS |

- Liquid Glass は **1 つの要素に 4 層を重ねる**材質表現（`backdrop-filter` / グラデーション本体 / `::before` の鏡面リム / `::after` のグレイン）。Tailwind のユーティリティで書くと、1 要素に 20 個以上のクラスが並び、`@supports` ガードや `mask-composite` は結局任意 CSS に逃げることになる。
- レーンの色は `--lane-h` という**色相 1 個のカスタムプロパティ**を React から渡し、CSS 側で `hsl()` を組み立てている。Tailwind の静的クラス生成とは相性が悪い。
- 依存が 1 つ減り、ビルドステップも 1 つ減る。

## Liquid Glass の実装

- `backdrop-filter: blur() saturate() brightness()` が土台。
- **`feTurbulence` + `feDisplacementMap` の SVG フィルタ**を `backdrop-filter: url(#liquid-glass)` として重ね、背景を**ぼかすのではなく屈折させる**。これが「ガラス」と「すりガラス」の差。`@supports` でガードしてあり、非対応ブラウザは通常のぼかしに落ちる。
- 真っ黒な背景では屈折させる対象が無いので、**低輝度のオーロラ**を 3 つ置いてある（`opacity: 0.3` + 中心以外を黒に落とすビネット）。黒ベースを壊さずガラスに表情を与えるための光源。
- `::after` のグレインはブラー面の「のっぺり」を壊し、材質として見せるため。

## スケルトンローディング

- **全画面**。トップバー・レール・カード 5 枚を実レイアウトと同じ箱で描くので、復帰がジャンプではなくクロスフェードになる。
- **ただしコンポーザーはスケルトンの外**（`z-index` で上）。入力欄は最初のフレームからマウント済み・フォーカス済みで、**ロード中でもそのままタイプできる**。1 打鍵目でスケルトンは即座に消える。
- 最低表示時間 420 ms。速すぎるロードがチラつきに見えるのを防ぐ。

## テスト: Vitest + 実ブラウザ操作

- **Vitest** は純ロジック（ステータス機械・パーサ・フリック判定・AI マージ・セッション署名）を workerd 無しで回すため。61 件、1 秒強。
- **ブラウザ操作による検証**は、ジェスチャ・フォーカス・オフライン・OAuth ゲートのように単体テストで証明できない部分に対して実施。結果は [TESTS.md](TESTS.md)。
- **Playwright を入れなかった理由:** ブラウザバイナリのダウンロードが CI と開発環境の両方に重く、今回の E2E は実ブラウザで直接実行・確認した。回帰が増えた段階で入れるのが妥当。

## 却下した案

- **Next.js + Vercel** — Cloudflare 完結という前提から外れる。
- **PWA の Service Worker によるオフライン** — localStorage で capture の即時性は既に満たしており、SW はキャッシュ無効化の難しさを持ち込む。インストール可能性だけが必要なら manifest で足りる（入れてある）。
- **Workers AI のストリーミング** — 整形結果は 1 行。ストリームする意味が無い。
